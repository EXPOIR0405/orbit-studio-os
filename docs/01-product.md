# 제품 설계

## 판단

포트폴리오 프로젝트로 가치가 있다. 도메인 업무 설계, 멀티 에이전트 조정, 평가, 사람의 개입, 실행 추적을 하나의 제품 문제로 보여줄 수 있기 때문이다. 다만 ‘자율 회사’ 전체를 처음부터 구현하면 업무의 실효성보다 화면과 역할 이름이 먼저 늘어날 위험이 크다.

따라서 시작점은 **웹툰 운영자의 회차 공개 준비**다. 장기 비전은 스튜디오 운영이며, 첫 검증 대상은 한 가지 반복 업무다. 사업성·고객 수요·업무 절감 효과는 아직 검증하지 않았다.

## 사용자와 권한

| 주체 | 책임 | 허용되는 결정 |
| --- | --- | --- |
| CEO | 목표, 총예산, 정책 예외 | 운영 한도와 후속 외부 실행 정책 승인 |
| Human AI Operator | 미션 구성, 원고 검수, 작업 재배분 | 미션 시작·중단, 결과 수정·승인, 허용 범위 내 설정 선택 |
| Milo — 총괄 PD / Orchestrator | 계획 제안, 작업 배분, 결과 종합 | 허용된 역할과 도구 안에서만 계획 생성 |
| Specialist | 분야별 분석과 산출물 작성 | 입력을 읽고 자기 산출물의 새 버전 생성 |
| QA | 검증과 오류 보고 | 통과·재작업·사람 검토 권고. 승인권 없음 |

MVP는 단일 스튜디오·단일 운영자를 지원한다. CEO 화면은 정책과 요약을 보여주는 보조 화면이다. 실제 여러 사람이 접속하는 버전은 서버 권한 검증이 완성된 뒤 공개한다. 데모에서 역할 전환은 명확히 ‘시뮬레이션’으로 표시한다.

## 해결할 일

- 회차 공개 전에 설정 충돌·스포일러·출처 없는 주장을 발견한다.
- AI 분석의 근거를 원고 장면과 설정집 항목에서 바로 확인한다.
- 문제가 생긴 작업만 수정하고, 바뀐 결과에 의존하는 후속 작업을 재검증한다.
- 모델·지시문·도구 조합을 동일 과제로 비교해 역할별 설정을 선택한다.

## 범위

| MVP | 다음 단계 | 이번 프로젝트에서 보류 |
| --- | --- | --- |
| 텍스트 원고와 설정집 | 이미지 기반 콘티 검토 | 완성 웹툰 자동 제작 |
| 고정 역할 4개 + 조정자 | 검증된 역할 템플릿 추가 | 임의 도구를 가진 자율 직원 생성 |
| 계획 검토·제한된 재작업 | 여러 미션 동시 운영 | 무제한 자기 복제와 대화 |
| 읽기 전용 합성 자료 | 동의·권한이 확인된 내부 자료 | 실제 댓글 무단 수집 |
| 패키지 승인과 내보내기 | 외부 게시 커넥터와 별도 승인 | 자동 결제·계약·광고 집행 |
| Agent Lab 비교 화면 설계 | 후보 설정 평가와 활성화 | 모든 모델의 실시간 가격 비교 |

Agent Hiring은 핵심 차별화 후보지만, 첫 구현은 공개 준비 미션을 완성한 뒤 진행한다. 채용이란 사람을 대체한다는 판정이 아니라 **검증된 역할 설정 버전을 활성화하는 제품 표현**이다.

## 입력과 산출물

입력: 미션 목표, 대상 회차, 공개 시점, 설정집 버전, 원고 버전, 합성 독자 반응, 금지 표현, 실행 예산.

최종 패키지:

- 수정 원고 초안: 지정 장면의 대사·전개 수정안, 원문과의 차이, 수정 이유. 원본은 보존하고 QA와 운영자가 검토.
- 설정 일관성 보고서: 원고 위치, 설정집 항목, 문제 유형, 수정 권고.
- 독자 반응 요약: 표본 크기, 분류 기준, 빈도, 대표 예시, 해석 한계.
- 홍보 문안 3안: 대상 채널, 메시지 의도, 스포일러 점검.
- 공개 준비 체크리스트: 통과·미해결·사람 판단 항목.
- 실행 명세: 입력·역할·산출물 버전, 비용, 승인 기록.

연령 등급과 IP 판단은 자동 확정하지 않는다. 미션에 입력된 기준과 충돌 가능성을 표시하고 담당자가 결정한다.

## 성공 가설

측정 전 목표이며 실적이 아니다. 합성 데이터에서 통과해도 실제 스튜디오 성과로 일반화하지 않는다.

| 지표 | 초기 통과 목표 | 측정 |
| --- | --- | --- |
| 운영자 검토 시간 | 단일 에이전트 대비 중앙값 20% 감소 | 같은 과제를 순서를 바꿔 교차 비교 |
| 알려진 설정 오류 탐지 | 재현율 90% 이상 | 사전 정답이 있는 평가 세트 |
| 오류 지적의 정확성 | 정밀도 85% 이상 | 오탐도 포함한 사람 검수 |
| 사실 주장 근거 지원율 | 95% 이상 | 단순 링크 존재가 아니라 내용의 지지 여부 |
| 승인 전 외부 쓰기 | 0건 | 부정 경로·권한 테스트 |
| 실패 후 복구 | 완료 작업을 재호출하지 않고 재개 | 프로세스 종료·중복 요청 시나리오 |

비용 증가가 검토 시간 절감보다 큰 경우, 역할을 합치거나 고정 워크플로로 축소한다. 인건비 환산을 임의로 가정해 ROI를 주장하지 않는다.
