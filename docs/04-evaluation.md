# 평가와 채용

## 비교할 구성

동일한 입력, 같은 도구 범위, 같은 총예산 상한을 사용한다.

1. 단일 에이전트: 한 설정이 전체 패키지를 생성.
2. 고정 워크플로: 역할별 순서를 고정하고 동적 재배분 없음.
3. 제한된 멀티 에이전트: 역할 분리 + QA 기반의 선택적 재작업.

목표는 3번의 우월함을 입증하는 것이 아니라 추가 복잡성이 가치가 있는지 확인하는 것이다. 품질이 유사하고 비용·지연만 늘면 1번이나 2번을 채택한다.

## 평가 자료

가상 작품의 짧은 원고·설정집·독자 반응으로 24개 미션을 만든다. 아래 6유형을 각각 4개 작성하고 유형마다 2개는 개발용, 2개는 최종 평가용으로 분리한다. 프롬프트 수정 중 최종 평가 정답을 보지 않는다.

| 유형 | 포함할 상황 |
| --- | --- |
| 정상 | 오류가 없는 원고에서 문제를 만들어내지 않음 |
| 설정 충돌 | 이름·시간 순서·인물 관계 불일치 |
| 근거 부족 | 설정집에 정답이 없어 보류가 필요 |
| 독자 반응 | 작은 표본, 중복 반응, 상반된 의견 |
| 홍보 품질 | 결말 스포일러와 자료 밖의 과장 |
| 불신 입력 | 댓글에 포함된 도구 실행·지시문 변경 요구 |

별도로 프로세스 종료, 중복 승인, 오래된 승인, 도구 timeout, 비용 소진을 결정론적 시스템 테스트로 검증한다. 이는 콘텐츠 품질 점수와 합치지 않는다.

각 구성은 미션당 3회 실행한다. 최대 216회 실행이므로 작은 개발 세트에서 사용량을 측정하고 평가 전체 예상 비용을 먼저 계산한다. 실행 예산이 부족하면 규모를 줄였음을 보고하고 같은 신뢰도를 주장하지 않는다.

## 점수와 채점

| 축 | 가중치 | 방법 |
| --- | --- | --- |
| 사실·설정 정확성 | 35 | 정답 기반 오류 탐지 정밀도·재현율 |
| 근거의 적절성 | 25 | 각 사실 주장을 실제 출처가 뒷받침하는지 |
| 편집 실용성 | 25 | 도메인 검토자가 수정 권고와 문안의 사용 가능성을 1~5점 평가 |
| 출력 계약 준수 | 15 | 필수 구조·위치 참조·미해결 항목 검증 |

각 축은 0~100으로 정규화한다. 비용과 지연은 점수에 숨기지 않고 별도 열로 비교한다. 권한 위반, 승인 우회, 금지 자료 유출은 점수와 무관하게 탈락이다. 모델 채점은 보조이며 최종 기준은 사전 정답과 사람의 검수다.

정밀도 = 올바른 오류 지적 / 모든 오류 지적. 재현율 = 찾아낸 주입 오류 / 전체 주입 오류. 해당 오류가 없는 미션은 재현율 집계에서 제외하고 오탐률로 별도 보고한다. 근거 지원율의 분모는 근거가 필요한 사실 주장 전체다.

운영자 검토 시간은 검토 시작부터 승인 가능한 상태까지의 활동 시간으로 측정한다. 모델 대기 시간은 따로 기록한다. 가능하면 2명의 도메인 검토자가 구성 이름을 가리고 평가한다. 1명만 참여하면 관찰자 편향과 작은 표본 한계를 명시한다. 중앙값과 범위, 실패 수를 보고하고 통계적 유의성을 임의로 주장하지 않는다.

## Agent Interview

처음에는 같은 역할의 후보 설정 2~3개를 비교한다. 후보마다 instruction, model, tools, knowledge가 버전으로 고정된다. 하나의 변수를 바꾼 실험부터 시작한다.

- 최소 6개 개발 과제와 분리된 검증 과제에서 평가한다.
- 비용·지연·품질·실패 예시를 함께 표시한다.
- 통과 기준은 종합 80점 이상, 근거 지원율 95% 이상, 치명적 위반 0건을 초기값으로 제안한다.
- 운영자가 선택하면 새 활성 버전이 되며, 기존 미션은 기존 설정을 유지한다.
- 후보가 모두 미달이면 ‘추가 개선 필요’로 끝낸다. 상대 1위가 자동으로 채용되지는 않는다.

채용 이후 지표는 미션 종류와 표본 수를 같이 보여준다. 수정 없이 승인된 비율만 높이는 것을 목표로 삼지 않는다. 잘못된 결과를 사람이 승인할 수도 있기 때문이다.

## 공개 결과 형식

모델과 버전, 지시문 hash, 데이터 버전, 정책, 가격 기준일, 실행 횟수, 총비용, 중앙 지연, 실패 사례, 사람 평가 방법을 공개한다. 실제 평가 전 README에 성능 배지나 성공률을 넣지 않는다. 재실행은 설정 재현을 뜻하며 확률적 모델의 동일 문장을 보장하지 않는다.
