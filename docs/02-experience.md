# 화면과 시연

```text

현재 상태: 검수 대기  │ 다음 결정: 설정 충돌 1건
```

진행률은 완료된 계획 작업 수로 계산한다. 계획이 바뀌면 분모 변화와 이유를 표시한다. 예상 잔여 시간은 측정 근거가 생기기 전에는 표시하지 않는다.

글작가·편집은 지정 장면의 수정 원고를 별도 버전으로 제안한다. UI에서 원문·수정안·수정 이유를 비교하고 QA 검사 후 운영자가 채택한다.

## Missions

좌측은 계획과 의존성 그래프, 중앙은 선택한 작업 산출물, 우측은 근거·변경점·승인 패널이다.

- 노드 선택: 입력 버전, 담당 역할, 상태, 비용, 재시도 횟수.
- 근거 선택: 원문 위치와 해당 인용 부분을 함께 표시.
- 수정 요청: 문제 위치와 요구사항을 입력하고 영향받는 작업을 미리 보여줌.
- 직접 편집: 운영자 작성 버전을 생성하고 이후 QA를 다시 실행.
- 승인: 정확한 패키지 버전과 체크리스트를 명시. 근거가 바뀌면 이전 승인은 만료.
- 내보내기: 승인된 텍스트 패키지와 manifest. 연재 플랫폼에 게시됐다고 표현하지 않음.

오류 상태는 ‘네트워크 재시도 중’, ‘예산 소진으로 중지’, ‘근거 없음’, ‘운영자 판단 필요’를 구분한다. 색 외에도 텍스트와 아이콘으로 상태를 표현한다. 그래프를 사용할 수 없는 사용자를 위한 동일 정보의 표와 키보드 탐색을 제공한다.

## Organization

CEO → Operator → 총괄 PD Milo → 글작가·편집 / 독자 분석 / 마케팅 / 최종 검수를 표시한다. 기술 식별자는 Story / Audience / Campaign / QA로 유지한다. 조직 계층과 실제 작업 그래프는 별도 보기다. 모든 역할이 항상 실행 중인 것처럼 보이지 않게 한다.

프로필에는 역할, 활성 설정 버전, 허용 도구, 읽을 수 있는 자료, 평가 결과, 표본 수, 최근 실패를 표시한다. ‘승인율 91%’ 같은 숫자는 데이터가 쌓이기 전에는 빈 상태로 표시한다. 아바타와 별칭은 선택사항이다.

## Agent Lab

문제 입력 → 허용 역할 템플릿 선택 → 후보 설정 2~3개 → 동일 과제로 Interview → 품질·비용·지연 비교 → 운영자가 활성화.

후보의 이름보다 실제 모델·지시문·도구·자료 버전 차이를 보여준다. 후보 전원이 최소 기준 미달이면 채용 버튼을 비활성화한다. 변경된 설정은 진행 중 미션에 적용하지 않고 다음 미션부터 사용한다. 기존 설정으로 롤백할 수 있다.

## Audit

미션·작업·에이전트 설정·승인자·기간으로 필터링한다. 각 이벤트는 관련 산출물과 입력으로 연결한다. 보여주는 것은 실행 이력, 짧은 판단 요약, 도구 결과와 근거다. 모델 내부 추론 원문을 요구하거나 저장하지 않는다.

## 5분 데모 대본

모든 수치와 작품 내용은 합성 시나리오다. 녹화용 재생 모드는 실제 실행과 분리해 표시한다.

1. 0:00 — 운영자가 《별빛식당》 EP.12 공개 준비 미션과 비용 상한을 입력한다.
2. 0:40 — Milo의 계획을 검토한다. Story와 Audience가 독립 작업임을 확인한다.
3. 1:20 — Story가 설정집의 인물 이름과 원고 S04의 불일치를 근거와 함께 제시한다.
4. 2:00 — QA가 홍보 문안에 결말 스포일러가 있음을 탐지한다. 운영자가 문안 수정만 요청한다.
5. 2:50 — Story·Audience 결과는 유지되고 Campaign과 QA만 새 버전으로 실행된다.
6. 3:40 — 이전 문안과 변경 문안, 비용 차이, 검증 결과를 비교한다.
7. 4:20 — 운영자가 패키지 버전을 승인하고 내보낸다. 실제 게시가 아님을 표시한다.
8. 4:50 — Audit에서 입력부터 승인까지 추적한다. Agent Lab은 후속 확장 설계로 소개한다.

성공 경로 외에 서비스 재시작 후 복구, 예산 소진, 근거 부족 중 하나를 별도 1분 데모로 준비한다.
